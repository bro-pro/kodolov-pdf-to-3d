# KODOLОV — PDF → 3D → quantities → Excel

## Что это

KODOLОV — прототип автоматизации обработки архитектурных и интерьерных планов:

```text
PDF / CAD
   ↓
извлечение геометрии + OCR
   ↓
определение масштаба
   ↓
Project Model (JSON)
   ↓
3D-модель (GLB)
   ↓
количественные показатели
   ↓
Excel
```

Pipeline рассчитан прежде всего на векторные PDF, содержащие CAD-геометрию.

Основные задачи:

* распознавание стен;
* восстановление помещений;
* определение дверей и окон;
* определение масштаба;
* построение параметрической модели;
* расчёт площадей, длин, объёмов и проёмов;
* генерация GLB;
* эвристическая расстановка базовой мебели;
* экспорт количеств в Excel.

## Структура pipeline

Главная точка запуска:

```text
run_pipeline.py
```

Она последовательно запускает:

```text
PDF
 ↓
plan_to_3d_p2_5.py
 ↓
model.glb + model.json
 ↓
add_furniture_p2_6.py
 ↓
model_furnished.glb + model_furnished.json
 ↓
export_excel_p2_6.py
 ↓
model_estimate.xlsx
```

Старые версии `p2_0`, `p2_1`, `p2_2`, `p2_3`, `p2_4` являются промежуточными версиями разработки и вручную не запускаются.

Для обычного запуска также не требуются debug-режимы.

## Установка

Python 3.10+ рекомендуется.

Создание виртуального окружения:

```bash
python -m venv venv
source venv/bin/activate
```

Установка Python-зависимостей:

```bash
pip install -r requirements.txt
```

### OCR

Для OCR используется Tesseract.

На Linux:

```bash
sudo apt install tesseract-ocr
```

Для русскоязычных подписей рекомендуется также установить языковой пакет:

```bash
sudo apt install tesseract-ocr-rus
```

Проверка:

```bash
tesseract --version
tesseract --list-langs
```

Для текущих векторных планов OCR является дополнительным механизмом. Основная геометрия извлекается непосредственно из PDF/CAD.

## Как запускать

### `projectfortest.pdf`

```bash
python run_pipeline.py projectfortest.pdf --print-scale 50
```

### Headliner

В Headliner несколько типов чертежей. Для построения модели используется лист с обмерным планом:

```bash
python run_pipeline.py "Дизайн-проект ЖК Headliner 29.11.pdf" --page 3 --print-scale 50
```

`--page` начинается с нуля, поэтому `--page 3` означает четвёртую страницу PDF.

## Определение масштаба

Основной источник масштаба — реальные размерные цепочки, извлечённые из PDF/CAD.

Если в документе доступны CAD-размеры, pipeline:

1. находит слой размеров;
2. извлекает геометрию размерных линий;
3. распознаёт числовые значения через OCR;
4. сопоставляет значения с геометрией размерных цепочек;
5. отбрасывает выбросы;
6. рассчитывает робастный масштаб.

Например, в Headliner размерные цепочки позволили получить масштаб автоматически с высокой уверенностью.

`--print-scale 50` используется как fallback для документов, где размерные данные недоступны или недостаточно надёжны.

Таким образом, печатный масштаб не является единственным источником истины для геометрии PDF.

## Проверенные тестовые проекты

Pipeline проверен на двух разных типах исходных PDF.

### 1. `projectfortest.pdf`

Векторный план с:

* CAD-геометрией стен;
* текстовыми подписями помещений;
* дверями и окнами;
* без отдельного CAD-слоя размерных цепочек.

Для этого проекта масштаб задаётся через:

```bash
--print-scale 50
```

Проверяются:

* стены;
* помещения;
* двери;
* окна;
* связи помещений со стенами;
* связи стен с проёмами;
* площади и количественные показатели;
* 3D-модель;
* мебель;
* Excel-экспорт.

### 2. `Дизайн-проект ЖК Headliner 29.11.pdf`

CAD-PDF с отдельными слоями:

```text
0          — основная геометрия
двери      — дверная геометрия
_Размеры   — размерные цепочки
```

Для модели используется четвёртая страница PDF:

```bash
--page 3
```

В этом проекте pipeline автоматически использует размерные цепочки для определения масштаба.

Проверяются:

* восстановление помещений из CAD wall grid;
* CAD-слой дверей;
* CAD-слой размеров;
* OCR размерных значений;
* автоматическая калибровка масштаба;
* стены и проёмы;
* Project Model;
* GLB;
* Excel.

Оба проекта проходят полный pipeline:

```text
PDF
 ↓
3D + JSON
 ↓
furniture
 ↓
Excel
```

Книга с:

* количественными показателями;
* сводкой;

## Мебель

Расстановка мебели выполняется отдельным эвристическим модулем.

Типовые объекты выбираются по геометрии помещений и проверяются на:

* попадание в доступный контур;
* пересечения;
* соответствие базовой геометрии помещения.

Это демонстрационная автоматизация, а не полноценный интерьерный дизайн.

## Архитектура

```text
PDF / CAD geometry
       ↓
dimensions / OCR
       ↓
scale calibration
       ↓
deterministic Project Model
 ├── walls
 ├── rooms
 ├── doors
 ├── windows
 ├── floor / ceiling
 └── topology
       ↓
quantities
       ↓
GLB
       ↓
Excel / future estimate
```

AI/Ollama при дальнейшем развитии может использоваться для семантической классификации неоднозначных элементов.

При этом метрическую геометрию и количественные расчёты предпочтительно получать детерминированно из PDF/CAD.

## Ограничения текущего прототипа

Разные PDF могут содержать разные CAD-слои, типы примитивов и способы оформления. Поэтому алгоритм рассчитан на адаптацию, но не гарантирует одинаковую полноту распознавания для любого проектного PDF.

Особенно неоднозначными могут быть:

* семантические названия помещений;
* сложные составные стены;
* нестандартные дверные блоки;
* окна, представленные нестандартными символами;
* планы, где геометрия является только растровым изображением.

Для промышленного применения следующим этапом нужны:

* regression-набор эталонных проектов;
* confidence/validation;
* расширенная классификация объектов;
* более глубокая обработка нестандартных CAD-структур.
