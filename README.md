# KODOLОV — PDF → 3D → quantities → Excel

## Что это

Прототип автоматизации строительных смет:

PDF-план → извлечение векторной геометрии → масштабирование → стены/проёмы/помещения → 3D GLB → Project Model JSON → Excel.

3D-модель используется как промежуточный и визуально проверяемый результат. Основная цель — получить параметрическую геометрию и количественные показатели для дальнейшего формирования сметы.

## Что установить

Требуется:

- Python 3.10+ (рекомендуется 3.11/3.12)
- `pip`

Установить зависимости:

```bash
python -m venv .venv
```

Windows:

```bash
.venv\Scripts\activate
```

macOS/Linux:

```bash
source .venv/bin/activate
```

Затем:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Проверка:

```bash
python -c "import fitz, trimesh, shapely, openpyxl, numpy, pytesseract, cv2; print('OK')"
```

### Что устанавливать НЕ нужно

Для текущей версии не требуются:

- Ollama
- Blender
- Revit
- SketchUp
- AutoCAD

Blender можно использовать отдельно для просмотра готового `.glb`.

### OCR для CAD-размеров

Для автоматического чтения размерных цепочек из CAD-PDF проект использует `pytesseract` + OpenCV. Python-зависимости устанавливаются через `requirements.txt`. Дополнительно в системе должен быть установлен Tesseract OCR.

Для русских подписей и размерных обозначений рекомендуется установить языковой пакет `rus`. Проверка:

```bash
tesseract --list-langs
```

В минимальном случае достаточно `eng` для цифровых размеров. Если Tesseract или Python OCR-зависимости недоступны, проект не падает: он явно сообщает об отключённом OCR и использует fallback-масштаб.

## Как запускать

### 1. Основное тестовое PDF

```bash
python run_pipeline.py projectfortest.pdf --print-scale 50
```

### 2. PDF Headliner

В Headliner несколько типов чертежей. Для построения модели используется лист с обмерным планом.

```bash
python run_pipeline.py "Дизайн-проект ЖК Headliner 29.11.pdf" --page 3 --print-scale 50
```

`--page` начинается с нуля. Поэтому `--page 3` означает четвёртую страницу PDF.

## Что делает одна команда

`run_pipeline.py` автоматически запускает весь pipeline:

```text
PDF
 ↓
plan_to_3d_p2_5.py
 ↓
model.glb + model.json
 ↓
add_furniture_p2_6.py
 ↓
model_furnished.glb + model_furnished.json
 ↓
export_excel_p2_6.py
 ↓
model_estimate.xlsx
```

Поэтому **старые версии `p2_0`, `p2_1`, `p2_2`, `p2_3`, `p2_4` вручную запускать не нужно**. Это промежуточные версии разработки.

Также для обычного запуска не нужны `--debug`, `--door-debug` и `--show`.

## Результат

После запуска в рабочей папке появляются:

```text
model.glb
model.json
model_furnished.glb
model_furnished.json
model_estimate.xlsx
```

### GLB

3D-модель стен, пола, потолка и базовой мебели.

### JSON

Параметрическая Project Model с:

- помещениями;
- стенами;
- дверями;
- окнами;
- связями стен и проёмов;
- топологией;
- количествами;
- статусами и confidence.

### Excel

Книга с листами количественных показателей, сводкой, проёмами, мебелью и контролем.

## Масштаб

Основной источник масштаба — размерные цепочки PDF, если они доступны.

`--print-scale 50` является fallback/подсказкой для чертежей, где размерные данные не удалось надёжно извлечь.

Это важно, потому что фактический масштаб геометрии в PDF может зависеть от компоновки листа. Поэтому печатный масштаб не должен считаться единственным источником истины.

## Мебель

Расстановка мебели выполняется отдельным эвристическим модулем.

Типовые объекты выбираются по геометрии помещений и проверяются на попадание в доступный контур и пересечения.

Это демонстрационная автоматизация для тестового задания, а не полноценный интерьерный дизайн.

## Архитектура

```text
PDF / CAD geometry
       ↓
dimensions / OCR
       ↓
scale calibration
       ↓
deterministic Project Model
 ├── walls
 ├── rooms
 ├── doors
 ├── windows
 ├── floor / ceiling
 └── topology
       ↓
quantities
       ↓
GLB
       ↓
Excel / future estimate
```

AI/Ollama при дальнейшем развитии можно использовать для семантической классификации неоднозначных элементов, но метрическую геометрию и количественные расчёты предпочтительно получать детерминированно из PDF/CAD.

## Ограничения текущего прототипа

Разные PDF могут содержать разные CAD-слои, типы примитивов и способы оформления. Поэтому алгоритм рассчитан на адаптацию, но не гарантирует одинаковую полноту распознавания для любого проектного PDF.

Особенно неоднозначными могут быть:

- семантические названия помещений;
- сложные составные стены;
- нестандартные дверные блоки;
- окна, представленные нестандартными символами;
- планы, где геометрия является только растровым изображением.

Для промышленного применения следующим этапом нужны regression-набор эталонных проектов, confidence/validation и расширенная классификация объектов.
